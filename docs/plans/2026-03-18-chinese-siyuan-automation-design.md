# 中文思源自动化目录与脱敏设计

**日期：** 2026-03-18

## 目标

统一 `good_skills` 中所有自动写入思源笔记的技能，让它们都使用中文目录结构：

`AI自动化/<功能中文名>/<日报中文名>/<日期>`

同时清理仓库中的敏感信息和本地运行痕迹，整理 npm CLI 的发布链路，使仓库重新达到可公开发布状态。

## 当前问题

1. 思源写入逻辑分散在多个脚本中。
2. 不同技能各自决定 notebook/path，目录层级不统一。
3. 默认配置中存在个人域名、内网地址、Bark token、邮箱和收件人。
4. 仓库中混入了运行产物、缓存文件和个人路径。
5. npm CLI 实际位于 `packages/cli/`，但仓库根目录缺少清晰的发布说明和脱敏约束。

## 设计决策

### 1. 统一思源目录规范

所有自动化产物统一写入思源笔记本 `AI自动化`，目录采用：

`AI自动化/<功能中文名>/<日报中文名>/<日期>`

示例：

- `AI自动化/论文追踪/arXiv日报/2026-03-18`
- `AI自动化/科技资讯/每日早报/2026-03-18`
- `AI自动化/穿搭助手/穿搭日报/2026-03-18`
- `AI自动化/内容创作/无语哥选题/2026-03-18`

### 2. 共享思源写入层

在 `shared/` 下扩展统一思源模块，负责：

- 查找或创建目标笔记本
- 根据中文功能名和日报名生成目录路径
- 兼容当前思源 API
- 给各技能提供稳定入口，避免重复拼接 path 和手写 API 请求

### 3. 共享配置脱敏

在 `shared/config.py` 中移除任何真实默认值：

- `SIYUAN_HOST` 默认回退为本地地址
- `BARK_TOKEN` 默认置空
- `EMAIL_SENDER` 默认置空
- `EMAIL_RECIPIENTS` 仅从环境变量读取

所有技能统一通过共享配置读取环境变量，不再在脚本内部硬编码。

### 4. 技能脚本改造策略

优先改造“直接写思源”的日报/周报类技能：

- `arxiv-daily`
- `daily-newsletter`
- `daily-digest`
- `vibe-daily`
- `super-fitness`
- `super-wardrobe`
- `weekly-report`
- `wuyu-xiaohongshu`
- `siyuan-daily`

对于已经使用共享模块的技能，尽量只改调用参数。
对于仍然手写 `urllib` 的技能，迁移到共享写入器。

### 5. 仓库脱敏范围

需要处理的内容包括：

- 个人邮箱、收件人、SMTP 固定配置
- 个人域名、内网地址、默认 token
- Bark token、API key 占位写法过于接近真实格式的示例
- `__pycache__`、日报样例、测试产物、下载结果、个人路径引用
- 平台元数据中的个人邮箱或本地绝对路径

### 6. npm 发布链路

真实 npm 包位于 `packages/cli/package.json`，因此发布整理只围绕这条链路进行：

- 保持 CLI 包为唯一发布入口
- 清理仓库根目录和包目录中的敏感信息
- 补充发布前检查
- 在本机没有 Node/npm 的情况下，先把仓库整理到“可发布状态”，实际发布留到具备 npm 环境和登录态时执行

## 风险与边界

1. 当前机器缺少 `npm`，因此无法在本地跑 CLI 测试或直接发布。
2. 当前机器也未确认可用 Python 运行时，脚本级测试可能受限。
3. 思源目录重构会影响后续新增文档的落点，但不会自动迁移旧文档。
4. 这轮优先做“新写入统一”，不做历史文档批量搬迁。

## 验证标准

完成后应满足：

1. 所有目标技能写入思源时都落到中文目录结构下。
2. 仓库中不再包含硬编码个人邮箱、收件人、默认思源公网地址、默认 Bark token。
3. 运行产物和缓存文件被移除并加入忽略规则。
4. `packages/cli/package.json` 仍然可作为唯一 npm 发布入口。
5. 文档中明确说明配置方式和发布前检查方式。
